<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser `NEXT_LOCALE` cookie → server `resolveLocale()` | User-controlled cookie value crosses into a server-side dynamic `import()` path for message JSON |
| npm registry → `frontend/node_modules` | New build-time dependency (`next-intl`) enters the supply chain |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | `frontend/lib/i18n/request.ts` `resolveLocale()` | mitigate | Cookie value is validated against the `SUPPORTED_LOCALES` enum (`['en','vi']`) before use; any other value (including path-traversal-shaped strings) falls back to `DEFAULT_LOCALE`, so the dynamic `import(`../../messages/${locale}/teacher.json`)` path is always one of two fixed, known-safe strings — never attacker-controlled. |
| T-18-02 | Information Disclosure | `NEXT_LOCALE` cookie | accept | Cookie holds only a UI-preference enum value ('en'/'vi'), no PII, session token, or auth data; not marked HttpOnly-sensitive because it carries no secret. |
| T-18-03 | Denial of Service | Dynamic `import()` of `messages/{locale}/teacher.json` | mitigate | Same enum-validation as T-18-01 prevents an unresolvable import path from throwing an unhandled server error on every request. |
| T-18-SC | Tampering | `npm install next-intl` | mitigate | Already audited [Approved] in 18-RESEARCH.md's Package Legitimacy Audit (npm registry, 3+ yrs old, 50K+/wk downloads, github.com/amannn/next-intl, slopcheck OK) — no blocking human-verify checkpoint required for this specific package. |
</threat_model>

  <how-to-verify>
1. Run `cd frontend && npm run dev` and open the app in an incognito/private browser window (no cookies) at `/teacher/login`. Confirm the page renders in **Vietnamese** by default (D-07) — no LanguageSwitcher click needed to see this.
2. Log in as a teacher. Use the LanguageSwitcher in the header to switch to **English**. Click through all of: Dashboard, Classes (open create + edit modal), Students (open create/edit/approve/reset-password modals), Homework (open create modal, assign modal, a homework detail page, a session result page, the Try/Preview page for at least a PHONICS and a READING homework), Sessions, Tuition (all 3 tabs: config, generate records, report), Import, Schedule. 3. Switch back to **Vietnamese** via the LanguageSwitcher and repeat step 2's page-by-page click-through. Confirm every visible label, button, toast, and modal title is in Vietnamese with no stray English text.
4. On at least 3 pages (Dashboard, Homework list, Tuition), inspect the DOM/visible text for any raw translation-key-looking strings leaking through (e.g. `teacher.pages.classes.title` or `homework.toasts.save_error` appearing literally instead of translated text) — this indicates a missing key in one of the two `messages/{locale}/teacher.json` files that Task 2 of Plan 18-11 should have caught, but confirm visually here.
5. Confirm the Tuition report table's currency amounts (e.g. "100,000 VNĐ") look identical in both EN and VI (D-12 — currency must NOT change with language) and that any dates on the Sessions/Homework pages render in the same format regardless of language (D-13).
6. Refresh the page after switching locale — confirm the selected language persists across the reload (cookie-backed, D-06).

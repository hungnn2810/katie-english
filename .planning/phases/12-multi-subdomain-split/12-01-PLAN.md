<objective>
Create `frontend/middleware.ts` — the single file that makes subdomain routing work — and wire up local dev infrastructure (package.json scripts + docker-compose env vars).

The middleware reads the `Host` header (or `NEXT_PUBLIC_SUBDOMAIN` env var for local dev) to determine which role surface is active, then enforces route containment: admin.* serves only `/admin/**`, app.* serves only `/teacher/**`, student.* serves `/game/**` and `/login`. Root domain redirects 301 to `app.katie.vn`. Unrecognized subdomains get a 404 rewrite to `frontend/app/not-found.tsx`.

Per D-07, the middleware also reads only the cookie for the current subdomain (`admin-token`, `teacher-token`, `student-token`) to do a lightweight role check — if the cookie exists but decodes to the wrong role, it redirects to the current subdomain's login page (D-04 is handled by client layout guards; middleware only redirects unauthenticated users, not wrong-role users — wrong-role produces 403 from the layout).

Purpose: Without this file no subdomain isolation exists. All three decisions D-01/D-02 (local dev ports + env var), D-07 (cookie isolation), D-08 (root redirect), D-09 (unknown subdomains), and D-10 (route containment) are implemented here.

Output:
- `frontend/middleware.ts` (new file, ~80 lines)
- `frontend/package.json` modified: 3 new dev scripts
- `docker-compose.yml` modified: 4 new env vars in frontend service
</objective>

<task type="auto">
  <name>Task 1: Create frontend/middleware.ts with subdomain detection, route containment, and auth redirect</name>
  <files>frontend/middleware.ts</files>
  <action>
    Create `frontend/middleware.ts` as a new file. This is a Next.js Edge middleware — it must use only the `next/server` import and must NOT import from Node.js-only modules (no `fs`, `path`, `crypto`, etc.).

    Structure:

    1. Define the SUBDOMAIN_CONFIG map (per D-10):
       - key 'admin': cookieName 'admin-token', allowedPrefixes ['/admin'], loginPath '/admin/login'
       - key 'app': cookieName 'teacher-token', allowedPrefixes ['/teacher'], loginPath '/teacher/login'
       - key 'student': cookieName 'student-token', allowedPrefixes ['/game', '/login'], loginPath '/game/login'

    2. Define `detectSubdomain(req: NextRequest): 'admin' | 'app' | 'student' | 'root' | 'unknown'`:
       - First check `process.env.NEXT_PUBLIC_SUBDOMAIN` — if set and is one of 'admin'|'app'|'student', return it (per D-02 local dev).
       - Then read `req.headers.get('host') ?? ''`.
       - `host.startsWith('admin.')` → 'admin'
       - `host.startsWith('app.')` → 'app'
       - `host.startsWith('student.')` → 'student'
       - `host === 'katie.vn' || host === 'www.katie.vn'` → 'root'
       - else → 'unknown'

    3. Define `decodeJwtRole(token: string): string | null`:
       - Split token on '.', take index 1, call `atob()` on it, JSON.parse, return `payload.role ?? null`.
       - Wrap entire body in try/catch — return null on any error.

    4. Export the default `middleware(req: NextRequest)` function:

       a. Call `detectSubdomain(req)`.

       b. If 'root': return `NextResponse.redirect(new URL('https://app.katie.vn' + req.nextUrl.pathname, req.url), 301)` — per D-08. In local dev (NEXT_PUBLIC_SUBDOMAIN is set), this branch is unreachable; no special handling needed.

       c. If 'unknown': rewrite to `/not-found` using `NextResponse.rewrite(new URL('/not-found', req.url))` — per D-09.

       d. If one of 'admin'|'app'|'student':
          - Look up `config = SUBDOMAIN_CONFIG[subdomain]`.
          - Check route containment (D-10): if `pathname` does NOT start with any of `config.allowedPrefixes` AND is not one of `/`, `/_next/`, `/favicon.ico` (the matcher already excludes static assets, but login paths still need to pass through): return `NextResponse.rewrite(new URL('/not-found', req.url))`.
          - Read the cookie: `req.cookies.get(config.cookieName)?.value`.
          - If cookie present: decode role. If role does not match expected role for this subdomain (admin→'ADMIN', app→'TEACHER', student→'STUDENT'), do NOT redirect — return `NextResponse.next()` and let the client-side layout guard show the 403 page (D-04).
          - If cookie absent AND pathname is NOT one of config.loginPath / '/not-found': redirect to `config.loginPath` using `NextResponse.redirect(new URL(config.loginPath, req.url))`.
          - Otherwise (cookie absent but already on login path, or cookie present): return `NextResponse.next()`.

    5. Export `config` object:
       ```
       export const config = {
         matcher: ['/((?!_next/static|_next/image|favicon\\.ico).*)'],
       };
       ```

    Important constraints:
    - Do NOT call `verify` on the JWT (requires crypto, not available in Edge without polyfill) — only decode the base64 payload.
    - The root redirect URL uses `https://` hardcoded for production. In local dev, NEXT_PUBLIC_SUBDOMAIN prevents this branch from being reached.
    - Route containment check (step d, containment): the login path itself must be in `config.allowedPrefixes` implicitly — for 'admin' the login is at `/admin/login` which starts with `/admin`, so it passes. For 'student' the login is at `/game/login` which starts with `/game` (in allowedPrefixes). For 'app' the login is at `/teacher/login` which starts with `/teacher`. **Special case for app.* subdomain:** if `pathname === '/login'` exactly, redirect to `/teacher/login` — this handles existing bookmarks/links pointing to the old combined `/login` URL on the teacher domain. Add this check BEFORE the route containment check: `if (subdomain === 'app' && pathname === '/login') return NextResponse.redirect(new URL('/teacher/login', req.url))`.
    - The `/` root path on a subdomain should rewrite to the subdomain's default (e.g., on 'app', `/` is not under `/teacher` — rewrite to `/not-found` or redirect to the allowedPrefix default). Redirect `/` to the first allowed prefix (e.g., `/teacher` for 'app', `/admin` for 'admin', `/game/homework` for 'student').
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Next.js middleware (Edge) | All HTTP requests cross here; Host header is the trust boundary for subdomain routing |
| Middleware → JWT cookie payload | Role claim decoded from base64 without signature verification |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01-01 | Spoofing | Host header — attacker sets `Host: admin.katie.vn` on direct connection | mitigate | In production, a reverse proxy (nginx/Vercel/Cloudflare) must be the only entry point; middleware is the last line, not the first. Document in SECURITY.md. Internal network access to Next.js port bypasses this gate — acceptable for a school app with no public server exposure. |
| T-12-01-02 | Tampering | NEXT_PUBLIC_SUBDOMAIN env var — sets subdomain without Host | accept | This var is only set in local dev scripts and docker-compose.yml; it is never user-controlled. In production the var is unset and Host header takes over. Risk: misconfigured prod deploy with var still set — mitigate by convention: document that this var must NOT be set in production environment. |
| T-12-01-03 | Elevation of Privilege | JWT role decoded without signature verification in middleware | mitigate | Middleware uses decoded role only for unauthenticated redirect (skip login redirect if already logged in). The actual authorization decision is made by NestJS AuthGuard on the backend, which fully verifies the JWT. A forged cookie that passes the base64 decode check will still be rejected by NestJS on any real API call. Acceptable trade-off: Edge crypto libraries add complexity and the redirect decision is not a security boundary. |
| T-12-01-04 | Denial of Service | Root redirect loop (katie.vn → app.katie.vn → middleware on app subdomain sees root again) | mitigate | The redirect uses `https://app.katie.vn` as absolute URL, not relative. On `app.katie.vn` the subdomain detection returns 'app', not 'root', so the redirect branch is never entered again. No loop possible. |
| T-12-01-SC | Tampering | npm package installs | mitigate | No new packages installed in this plan (middleware uses only `next/server`, package.json scripts use built-in next CLI). No legitimacy audit required. |
</threat_model>

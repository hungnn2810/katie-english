<objective>
Improve the BFA Python service so speaking submissions are faster and safer to process: drop the unused word-level alignment from /transcribe (D-20), cap upload size at 100MB and audio duration at 5 minutes (D-21), and stop blocking the async event loop on espeak-ng (D-23). Also relax the TypeScript `WhisperXResult.words` typing so it accepts the new response shape (D-20 backend side).

Purpose: Saves ~300–800ms per speaking submission, prevents resource exhaustion from oversized/long uploads, and removes a known event-loop blocker in the phonics path. None of these touch the public NestJS API; they are runtime-only improvements.

Output:
- `bfa-service/main.py` with simpler /transcribe (no align), 100MB/5min caps, async-safe espeak.
- `bfa-service/Dockerfile` committed as-is (currently untracked).
- `backend/src/bfa/bfa.dto.ts` with `words?: WhisperXWord[]` (optional) so the new response shape `{text: string}` typechecks.
</objective>

    <threat severity="low">Event-loop starvation under concurrent /align calls (availability). Sync `subprocess.run()` in an async handler blocks the entire FastAPI worker; multiple concurrent phonics requests would serialize. Mitigation: T-02 wraps the call in `asyncio.to_thread()` so other async handlers (notably /transcribe and /health) continue serving while espeak runs. Only triggered in the espeak-fallback path (no DB phoneme data).</threat>

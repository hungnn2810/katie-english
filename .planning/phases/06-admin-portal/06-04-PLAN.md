<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /admin/classes/* | Guarded by AdminGuard on all three routes |
| AdminUpdateClassDto → prisma.class.update | Mass-assignment surface — admin can change name/code/dates/status/schedule but NOT teacherId (D-11) |
| AdminClassesService.delete → multiple Prisma tables | Transactional cleanup of dependents to avoid FK violations |
| Teacher's POST /classes (existing) → Class.teacherId | New field written from authenticated JWT, not from request body |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04-01 | Tampering / Privilege Escalation | AdminUpdateClassDto | mitigate | DTO has no `teacherId` field; service does not spread it; UI does not surface it. D-11 enforced at the type level. |
| T-06-04-02 | Tampering | Teacher attempting to set teacherId via body | mitigate | class.controller.create reads teacherId from `req.user.sub` (JWT payload), NOT from the request body. CreateClassDto remains free of teacherId. |
| T-06-04-03 | Tampering | Bulk-delete cascade | mitigate | Delete runs in a single `prisma.$transaction` — either every dependent is cleaned and the class is removed, or no state changes at all. |
| T-06-04-04 | Information Disclosure | findAll teacher relation | accept | Returns teacher name + upn (email). Admin-scope endpoint behind AdminGuard. No leakage outside admin. |
| T-06-04-05 | IDOR | PUT/DELETE /admin/classes/:id | mitigate | AdminGuard ensures only ADMIN-role JWT reaches the route; route uses ParseIntPipe for id type safety. `findById` throws 404 for any non-existent id. |
| T-06-04-06 | DoS | Transactional delete on large class | accept | Worst case scales with number of sessions per class — bounded by realistic platform usage (single platform admin, small classes). No mitigation needed. |
| T-06-04-07 | Repudiation | Class deletion | accept | Single admin; audit logging deferred (CONTEXT D-04). |
</threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /admin/classes/* | Guarded by AdminGuard on all three routes |
| Query string teacherId → controller | Untrusted string; NaN-guarded before reaching Prisma (REVIEW L-01) |
| AdminUpdateClassDto → prisma.class.update | Mass-assignment surface — admin can change name/code/dates/status/schedule but NOT teacherId (D-11) |
| AdminClassesService.delete → multiple Prisma tables | Scoped transactional cleanup using interactive $transaction (REVIEW H-01) — only this class's students' sessions are removed; assignments shared with other classes survive (REVIEW M-01) |
| Teacher's POST /classes (existing) → Class.teacherId | New field written from authenticated JWT, not from request body |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04-01 | Tampering / Privilege Escalation | AdminUpdateClassDto | mitigate | DTO has no `teacherId` field; service does not spread it; UI does not surface it. D-11 enforced at the type level. |
| T-06-04-02 | Tampering | Teacher attempting to set teacherId via body | mitigate | class.controller.create reads teacherId from `req.user.sub` (JWT payload), NOT from the request body. CreateClassDto remains free of teacherId. |
| T-06-04-03 | Integrity / Data Loss (REVIEW H-01 + M-01) | Bulk-delete cascade | mitigate | Delete runs inside a single `prisma.$transaction(async (tx) => { ... })` — interactive form supports the intermediate `findMany` reads required to capture studentIds + assignmentIds BEFORE issuing scoped deletes. The operation is atomic (all-or-nothing). It is also **scoped per-class**: only HomeworkSession rows for (assignmentId ∈ this class's assignments, studentId ∈ this class's students) are deleted; HomeworkAssignmentClass join rows for this class are removed, but the parent HomeworkAssignment row survives if any other HomeworkAssignmentClass row still references it. Students in OTHER classes that share an assignment retain their sessions. |
| T-06-04-04 | Information Disclosure | findAll teacher relation | accept | Returns teacher name + upn (email). Admin-scope endpoint behind AdminGuard. No leakage outside admin. |
| T-06-04-05 | IDOR | PUT/DELETE /admin/classes/:id | mitigate | AdminGuard ensures only ADMIN-role JWT reaches the route; route uses ParseIntPipe for id type safety. `findById` throws 404 for any non-existent id. |
| T-06-04-06 | DoS | Transactional delete on large class | accept | Worst case scales with `|class.students| × |class.assignments|` sessions — bounded by realistic platform usage (single platform admin, small classes). No mitigation needed. |
| T-06-04-07 | Repudiation | Class deletion | accept | Single admin; audit logging deferred (CONTEXT D-04). |
| T-06-04-08 | Input Validation (REVIEW L-01) | teacherId query string | mitigate | Controller calls `parseInt(teacherId, 10)` then explicit `isNaN` check — throws `BadRequestException('teacherId must be a number')` (HTTP 400) before Prisma sees the value. Non-numeric strings never reach the database layer. |

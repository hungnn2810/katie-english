## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → DELETE /admin/homework/:id | AdminGuard required; destructive irreversible action |
| Browser → DELETE /admin/students/sessions/:sessionId | AdminGuard required; destructive irreversible action |
| AdminHomeworkService.delete → multiple Prisma tables | Manual cascade (sessions → homework with cascade to assignments + assignment_classes + parts + reading_activities) |
| Frontend confirm dialog | Last-line defense against accidental destructive action; UI-SPEC dismiss-label rule enforced |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06-01 | Tampering | DELETE /admin/homework/:id reaching homework that belongs to a different teacher (cross-tenant) | mitigate | Admin is a global super-user (D-04) — by design, admin can delete any homework. AdminGuard enforces that only ADMIN-role JWTs reach the route. There is no per-teacher tenancy boundary to violate. |
| T-06-06-02 | Tampering / Integrity | Partial cascade leaving FK-violating orphans (e.g. sessions without parent assignment) | mitigate | Delete runs inside a single `prisma.$transaction(async (tx) => { ... })` — either every dependent is removed and the homework row goes, or no state changes at all. Manual smoke-test acceptance criteria run a `psql count(*)` against every related table after delete. |
| T-06-06-03 | Tampering | Mass-assignment / DTO bypass | mitigate | Both new routes are DELETE with no body; admin-homework controller has no PUT/POST surface. No DTO is parsed. |
| T-06-06-04 | IDOR | DELETE /admin/students/sessions/:sessionId fed an arbitrary id | mitigate | AdminGuard restricts to ADMIN role; `ParseIntPipe` enforces integer; `findSessionById` throws 404 for non-existent ids before delete runs. Admin is a global super-user by design — any session is in scope. |
| T-06-06-05 | Repudiation | Destructive action has no audit log | accept | CONTEXT D-04 establishes a single platform admin; audit logging is deferred. Surface the gap in SUMMARY so future phases can revisit. |
| T-06-06-06 | Denial of Service | $transaction over a homework with thousands of sessions | accept | Platform scale is assumed small. Worst-case bounded by realistic platform usage. No mitigation needed in this MVP; revisit if submission counts approach 10⁴ per homework. |
| T-06-06-07 | Information Disclosure | findAll() exposes every homework name + counts to the admin browser | accept | Admin-only endpoint behind AdminGuard. No data crosses the admin trust boundary. |
| T-06-06-08 | Spoofing | Admin token replay against DELETE endpoints | accept | Token expiry inherited from plan 06-02 admin-auth (out of scope here). The destructive action is authenticated; loss of admin credentials is the documented mitigation, not in-route checks. |
| T-06-06-09 | Tampering | UI dismiss-button mislabeled "Cancel" (would violate UI-SPEC dismiss rule and confuse user about reversibility) | mitigate | Acceptance criteria include `grep -c "'Cancel'\|>Cancel<" === 0` for both pages. Human-verify task explicitly checks dismiss-button labels read "Keep homework" / "Keep session". |

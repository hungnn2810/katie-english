## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /admin/students/* | Two GET routes guarded by AdminGuard from plan 06-01 |
| AdminStudentsService → cross-table reads | Pulls Student + Class + User (teacher) + HomeworkSession + Homework into one response |
| Frontend /admin/students page | Reads admin_token from localStorage via adminAuthHeaders |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05-01 | Information Disclosure | findAll returning teacher.upn (email) and student.fullname | accept | Endpoints are admin-only (AdminGuard rejects non-ADMIN JWTs). Single platform admin per CONTEXT D-04. Data does not cross the admin trust boundary. |
| T-06-05-02 | IDOR | GET /admin/students/:id/results | mitigate | AdminGuard ensures only ADMIN role; `ParseIntPipe` enforces integer id; `findById` throws 404 on non-existent ids before the results query runs. |
| T-06-05-03 | Authorization Bypass | Missing AdminGuard on the controller | mitigate | `@UseGuards(AdminGuard)` declared at the controller class — both routes inherit it. Acceptance criterion `grep -c "@UseGuards(AdminGuard)" === 1` enforces this. |
| T-06-05-04 | Tampering | Mass-assignment via request body | mitigate | Both endpoints are GET with no body. `admin-students.dto.ts` contains response interfaces only — no request DTO surface. |
| T-06-05-05 | DoS | findAll on a large student set (no pagination) | accept | Platform scale assumed small (single admin, modest student count). UI-SPEC states "Pagination: not required in v1 (load all)". Revisit when student count > 1000. |
| T-06-05-06 | Information Disclosure | Front-end localStorage admin_token | accept | Pattern established by plan 06-02 (admin-auth) — out of scope for this plan. |
</threat_model>

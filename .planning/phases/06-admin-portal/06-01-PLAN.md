<objective>
Lay the foundation for the admin portal: extend the data model to support an admin role and multi-teacher account data (email/name/phone/disabled), extend the JWT contract to allow `ADMIN` role tokens, add an `AdminGuard` for downstream admin controllers, and add an `ensureAdminUser` bootstrap that seeds the single env-driven admin account on startup (D-04).

This is Wave 1 and blocks every subsequent plan — admin login (Plan 02), teacher CRUD (Plan 03), classes (Plan 04), and students/sessions (Plan 05) all depend on this schema, JWT role, and guard.

Purpose: Establishing schema + guard + seed first means downstream plans never have to revisit data model decisions or re-derive auth.
Output: Migrated DB schema with ADMIN role; admin user auto-seeded on boot; AdminGuard exported from AuthModule.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /admin/auth/login (future, Plan 02) | Untrusted credential payload — handled by future plan |
| client → /admin/* (any future admin endpoint) | Bearer JWT crosses boundary; AdminGuard is the sole role-enforcement layer |
| env vars → ensureAdminUser | Process environment trusted; misconfiguration (missing vars) is a no-op, not a crash |
| Prisma client → Postgres | Internal trust boundary; existing connection pool, no change |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Spoofing | AdminGuard | mitigate | JWT signature verified via `TokenService.verify` (HS256, JWT_SECRET); reject if `verify` returns null. Role must equal 'ADMIN' — no fallback. |
| T-06-01-02 | Elevation of Privilege | JwtPayload role union | mitigate | Role union is the only path to ADMIN; existing TeacherGuard checks role === 'TEACHER' so an ADMIN-role token cannot access teacher-only endpoints either (defense in depth) |
| T-06-01-03 | Tampering | ensureAdminUser seed | mitigate | Hashes password via bcrypt cost 10 before DB insert; never logs the plaintext password; idempotent via `findUnique({where:{upn}})` short-circuit |
| T-06-01-04 | Information Disclosure | ADMIN_PASSWORD env var | accept | Secret remains in env, not committed to git; this phase does not introduce log statements that print env vars |
| T-06-01-05 | Repudiation | Admin user creation | accept | Single env-seeded admin; audit logging is out of scope (deferred — single super-admin only per CONTEXT D-04) |
| T-06-01-06 | Denial of Service | AdminGuard DB queries | mitigate | AdminGuard does NOT hit the DB on each request (no `prisma.user.findUnique`) — relies on signed JWT only. Pattern intentional per CONTEXT D-04 to avoid a hot-path DB lookup. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → POST /admin/auth/login | Untrusted body { email, password }; rate-limited via ThrottlerGuard (5/60s/IP) |
| Browser → GET /admin/stats | Bearer JWT crosses boundary; AdminGuard enforces ADMIN role |
| Browser → localStorage admin_token | Token sits in browser-controlled storage; reachable by any same-origin script |
| AdminShell → AdminLayout → admin pages | Layout is the sole client-side auth gate; routes inside the (admin) group rely on it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Spoofing | /admin/auth/login | mitigate | Server validates upn + bcrypt password; rejects non-ADMIN role users; same error message for all failure modes prevents user enumeration |
| T-06-02-02 | Tampering | Admin JWT | mitigate | JWT HS256 signed by JWT_SECRET; AdminGuard verifies signature and `role === 'ADMIN'` (no fallback role); 7-day expiry from existing TokenService |
| T-06-02-03 | Repudiation | Admin login attempts | accept | Single super-admin; audit logging deferred (CONTEXT D-04). Existing NestJS request log captures method+path. |
| T-06-02-04 | Information Disclosure | Login error messages | mitigate | UI-SPEC mandates one literal `'Invalid email or password'` for all three failure modes (no user, wrong role, wrong password). Frontend catch-all also forces the same string regardless of backend response text — including HTTP 429 throttle responses. |
| T-06-02-05 | Denial of Service | Admin stats endpoint | accept | Four parallel COUNT queries; submissions count uses indexed `completedAt` column. Single admin user — no realistic flood vector. Rate limiting deferred for stats. |
| T-06-02-06 | Elevation of Privilege | Teacher attempting admin login | mitigate | admin-auth.service `user.role !== UserRole.ADMIN` check rejects any non-ADMIN user even with valid credentials. Returns generic error to avoid revealing whether the email exists in another role. |
| T-06-02-07 | Tampering | Client-side AdminLayout auth gate | accept | AdminLayout is UX only; real security is the server-side AdminGuard on `/admin/stats` (and downstream `/admin/*` endpoints added by Plans 03-05). A bypass of the layout still hits a 401/403 on every API call. |
| T-06-02-08 | Information Disclosure | localStorage admin_token | accept | Standard browser storage trust model — same approach as existing teacher session. No XSS-introduced regression in this plan. |
| T-06-02-09 | Brute Force | Admin login credential guessing | mitigate | REVIEW M-02 — @nestjs/throttler `ThrottlerGuard` applied to `POST /admin/auth/login` with `{ name: 'admin-login', limit: 5, ttl: 60_000 }`. After 5 attempts per IP in 60s, ThrottlerException returns HTTP 429. The single seeded admin credential is no longer susceptible to high-rate guessing. |
| T-06-02-SC | Tampering | npm install @nestjs/throttler | mitigate | Package is the official NestJS rate-limit module (npmjs.com/package/@nestjs/throttler — published by the NestJS org, 1M+ weekly downloads). Legitimacy is verifiable at install time. No `[ASSUMED]`/`[SUS]` status. |

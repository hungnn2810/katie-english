# Plan 05: BFA Service Hardening

**Goal:** Harden bfa-service against oversized inputs, reduce per-request thread pool allocation, and make operational thresholds configurable via environment variables.

**Scope (bfa-service/main.py only):**
- Input validation for word / target_text
- Shared module-level ThreadPoolExecutor
- Env-var configurable thresholds

---

## Task 1 — Input Length Limits

**Read first:** `bfa-service/main.py` lines 43–50 (env var block), 370–407 (`/align` handler), 578–609 (`/analyze` handler), 965–992 (`/analyze-speaking` handler)

**Action:**

Add two new env vars to the module-level config block (after `BFA_CONCURRENCY`):

```
MAX_WORD_LENGTH = int(os.getenv("BFA_MAX_WORD_LENGTH", "200"))
MAX_TARGET_TEXT_LENGTH = int(os.getenv("BFA_MAX_TARGET_TEXT_LENGTH", "2000"))
```

In `_align_impl`: after the `len(expected) > MAX_EXPECTED_PHONEMES` check, add:
```python
if len(word) > MAX_WORD_LENGTH:
    raise HTTPException(status_code=400, detail="word is too long")
```

In `_analyze_impl`: same guard after the expected_phonemes check.

In `_analyze_speaking_impl`: after `target_text = target_text.strip()`, add:
```python
if len(target_text) > MAX_TARGET_TEXT_LENGTH:
    raise HTTPException(status_code=400, detail="target_text is too long")
```

**Acceptance criteria:**
- `POST /align` with `word` of 201+ chars returns `{"detail": "word is too long"}` HTTP 400
- `POST /analyze-speaking` with `target_text` of 2001+ chars returns `{"detail": "target_text is too long"}` HTTP 400
- `POST /align` with `word` of exactly 200 chars does not return 400 (passes through to normal processing)

## Task 2 — Shared ThreadPoolExecutor

**Read first:** `bfa-service/main.py` lines 643–650 (`_analyze_sync` pool block), 910–915 (`_analyze_speaking_sync` pool block)

**Action:**

After the `REQUEST_SEMAPHORE` declaration (around line 50), add:
```python
THREAD_POOL = concurrent.futures.ThreadPoolExecutor(max_workers=2)
```

In `_analyze_sync`: replace `with concurrent.futures.ThreadPoolExecutor(max_workers=2) as pool:` with direct use of `THREAD_POOL`:
```python
transcribe_fut = THREAD_POOL.submit(_transcribe_wav, wav_path, word)
align_fut = THREAD_POOL.submit(_run_alignment, wav_path, word, expected, espeak_fallback, True)
transcription_text = transcribe_fut.result()
align_result = align_fut.result()
```

In `_analyze_speaking_sync`: same replacement — remove the `with ... as pool:` wrapper, submit directly to `THREAD_POOL`.

Do NOT shutdown the pool explicitly (it lives for the process lifetime).

**Acceptance criteria:**
- No `concurrent.futures.ThreadPoolExecutor(` constructor calls remain inside `_analyze_sync` or `_analyze_speaking_sync`
- `THREAD_POOL` is defined at module level (outside any function)
- `POST /analyze` still returns a valid response (functional regression test)

## Task 3 — Configurable Operational Thresholds

**Read first:** `bfa-service/main.py` lines 43–50 (env var block), 271–289 (`has_sufficient_energy`), 674–690 (`_transcription_matches_word`), 941 (`matched_words` threshold)

**Action:**

Add three new env vars to the module-level config block:
```python
ENERGY_THRESHOLD_DB = float(os.getenv("BFA_ENERGY_THRESHOLD_DB", "-50.0"))
TRANSCRIPTION_MATCH_THRESHOLD = float(os.getenv("BFA_TRANSCRIPTION_MATCH_THRESHOLD", "0.5"))
MIN_WORD_SCORE = int(os.getenv("BFA_MIN_WORD_SCORE", "70"))
```

Change `has_sufficient_energy` signature to accept optional threshold parameter with module default:
```python
def has_sufficient_energy(wav_path: Path, threshold_db: float = ENERGY_THRESHOLD_DB) -> bool:
```
(All call sites pass no explicit threshold, so they pick up the module default automatically.)

In `_analyze_sync` and `_align_sync`: the `_transcription_matches_word` call hardcodes `threshold=0.5`. Change to:
```python
_transcription_matches_word(transcription_text, word, threshold=TRANSCRIPTION_MATCH_THRESHOLD)
```

In `_analyze_speaking_sync` line ~941: change `if w["score"] >= 70` to:
```python
matched_words = sum(1 for w in word_results if w["score"] >= MIN_WORD_SCORE)
```

**Acceptance criteria:**
- `has_sufficient_energy` function signature default is `ENERGY_THRESHOLD_DB` (not literal `-50.0`)
- No literal `0.5` passed to `_transcription_matches_word` from `_analyze_sync` or `_analyze_speaking_sync`
- No literal `70` in `matched_words` calculation in `_analyze_speaking_sync`
- `BFA_ENERGY_THRESHOLD_DB`, `BFA_TRANSCRIPTION_MATCH_THRESHOLD`, `BFA_MIN_WORD_SCORE` all appear in env var block
- Setting `BFA_MIN_WORD_SCORE=100` via env makes all words below perfect score count as unmatched

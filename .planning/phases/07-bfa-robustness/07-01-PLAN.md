<objective>
Add five audio-quality gates to bfa-service so that bad inputs return structured, actionable error responses instead of silently scoring 0. Five gates (D-01 length, D-02 loudnorm normalization, D-03 RMS energy, D-04 ASR confidence, D-05 language mixing) are inserted at identical relative positions inside both `/analyze` (phonics) and `/analyze-speaking` (multi-word) handlers. All gates use the canonical D-07 error shape `{success: false, error: <code>, message: <human_readable>}`. New pytest suite (`bfa-service/test_bfa.py`) exercises every gate plus the happy path; D-02 loudnorm is verified by inspecting the ffmpeg command string.

Purpose: Phase 7 success criterion 1–4 ("Submitting a 0.3s clip returns HTTP 400 with `error: audio_too_short` — no score computed", same for silence/wrong language/no speech) cannot pass without these gates wired into the service. Without D-02 loudnorm, ASR quality varies between cheap-tablet and good-mic recordings, undermining D-04's empty-transcript detection. D-08 mandates a pytest suite — the file does not yet exist (`bfa-service/` currently contains only `main.py`, `requirements.txt`, `Dockerfile`).

Output:
- `bfa-service/main.py` modified: 3 new stdlib imports (math, struct, wave), 1 new third-party import (langdetect.detect_langs), 3 new env constants, 2 new helpers (`_wav_duration_s`, `_rms_dbfs`), `_to_wav` body updated with loudnorm filter, 5-gate block inserted in both `/analyze` and `/analyze-speaking`.
- `bfa-service/requirements.txt` appended with `langdetect==1.0.9`.
- `bfa-service/test_bfa.py` created with FastAPI TestClient + monkeypatched `_groq_transcribe` covering all 5 gate conditions + happy path + helper unit tests.
- `bfa-service/Dockerfile` unchanged in structure; `pip install -r requirements.txt` will pick up langdetect automatically.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → `/analyze` and `/analyze-speaking` | Untrusted multipart audio uploads cross the FastAPI boundary; Form-field strings (`word`, `target_text`) are also untrusted. |

## Spacing Scale

Inherits the established project scale. Phase 2 introduces no new tokens.

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | gap-1, p-1 | Icon gaps, drag handle margin |
| sm | 8px | gap-2, p-2 | Badge gaps, word choice button spacing |
| md | 16px | p-4, gap-4 | Card internal padding, activity section spacing |
| lg | 24px | p-6, gap-6 | Creation page card outer padding, game page sections |
| xl | 32px | mb-8, py-8 | Major layout gaps, result screen hero padding |
| 2xl | 48px | py-12 | Page-level vertical centering (result screen) |
| 3xl | 64px | — | Not used in this phase |

Exceptions:
- Image card in matching grid: 100–120px square (`w-24 h-24` = 96px or `w-28 h-28` = 112px) — fixed square, not on the spacing scale. Use `w-28 h-28` (112px) consistently.
- Matching image card: minimum 44px touch target satisfied by full card click area (112px × 112px >> 44px).
- Word choice buttons (matching + fill-blank): `py-3 px-6` (12px/24px) on `rounded-full` — minimum 44px height satisfied by `py-3` (24px + line-height = ~44px).
- Drag handle area: minimum 44px touch target via `p-3` (12px padding) on a 20px icon = 44px hit area.

## Animation Spec

All animations are CSS keyframe via Tailwind `animation` + `keyframes` config. These extend the existing `fadeIn` and `slideUp` animations in `tailwind.config.js`.

| Animation | Trigger | Duration | Keyframe | Element |
|-----------|---------|----------|----------|---------|
| Pair lock (correct) | Correct image-word match | 300ms | opacity 1 → 1 (no flash needed; border color change is sufficient) | Locked pair image card + word button |
| Shake (incorrect) | Wrong image-word match; wrong fill-blank answer | 400ms | `shake`: translateX 0 → -8px → 8px → -6px → 6px → -4px → 4px → 0 | Incorrect image card + word button (matching); incorrect word choice button (fill-blank) |
| Celebration fade | All pairs locked; activity complete | 500ms delay then 300ms | opacity 1 → 0.6 → 0 on overlay; auto-advance to next activity | Matching activity container |
| Fill-blank correct flash | Correct choice selected | 400ms | bg-brand-green/20 opacity 1 → 0, then auto-advance | Correct choice button |
| Fill-blank wrong shake | Wrong choice selected | 400ms | Same `shake` keyframe as above | Wrong choice button only |
| Slide-up | Modal open, activity card mount | 200ms | Existing `slideUp` keyframe | Creation page activity cards, modals |
| Fade-in | Page load | 180ms | Existing `fadeIn` keyframe | Page container |

**Shake keyframe** (add to `tailwind.config.js` keyframes, consistent with existing pattern):
```
shake: {
  '0%, 100%': { transform: 'translateX(0)' },
  '20%':      { transform: 'translateX(-8px)' },
  '40%':      { transform: 'translateX(8px)' },
  '60%':      { transform: 'translateX(-6px)' },
  '80%':      { transform: 'translateX(4px)' },
}
```
Tailwind animation: `animate-shake: 'shake 0.4s ease-in-out'`

**Celebration moment (D-09):** When all pairs in a matching activity are locked, show a brief white opacity overlay (`bg-white/10 → bg-white/0`) on the activity container for 500ms, then auto-advance. No confetti or star burst — simple fade is sufficient and consistent with the existing session page auto-advance pattern.

    2. Add a new `VocabItem` model (D-02) with fields:
       - `id Int @id @default(autoincrement())`
       - `homeworkId Int`
       - `homework Homework @relation("VocabItems", fields: [homeworkId], references: [id], onDelete: Cascade)`
       - `imageUrl String`
       - `word String`
       - `phonemes String?` (JSON array of phoneme symbols — same pattern as `Word.phonemes`)
       - `order Int @default(0)`
       - `createdAt DateTime @default(now())`
       - `phonicsResults PhonicsItemResult[]` (back-relation for vocab scores stored in PhonicsItemResult — see Task notes below)
       - `@@index([homeworkId])`
       - `@@map("vocab_items")`

    3. Add to the `Homework` model a back-relation field: `vocabItems VocabItem[] @relation("VocabItems")`.

    4. Extend `PhonicsItemResult` to support vocab items per D-04 (reuse this model, no separate VocabItemResult):
       - Change `wordId Int` to `wordId Int?` (nullable — vocab rows have no HomeworkWord).
       - Change the `word` relation to `word HomeworkWord? @relation(fields: [wordId], references: [id], onDelete: Cascade)`.
       - Add `vocabItemId Int?`.
       - Add `vocabItem VocabItem? @relation(fields: [vocabItemId], references: [id], onDelete: Cascade)`.
       - REMOVE the existing `@@unique([sessionId, wordId])` constraint — it is invalid once `wordId` is nullable and a session can now key on either `wordId` or `vocabItemId`. Replace it with two scoped uniqueness guards using Prisma named unique indexes is NOT supported on nullable composite cleanly, so instead add: `@@unique([sessionId, wordId])` is removed entirely and uniqueness is enforced at the application layer in 08-02 via upsert-by-find. Document this in the SUMMARY.

    Do NOT add a separate VocabItemResult model — D-04 explicitly rejects that to avoid schema duplication.

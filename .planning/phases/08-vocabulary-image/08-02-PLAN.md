BfaService.analyze signature (backend/src/bfa/bfa.service.ts) — REUSE AS-IS, do not modify the signature:
```typescript
async analyze(audioBuffer: Buffer, mimeType: string, word: string, _expectedPhonemes: string[]): Promise<BfaAnalyzeResult>
```
Note: the current engine is Azure Pronunciation Assessment (PA), NOT the old Python bfa-service. There is
NO `SIMILAR_PAIRS` frozenset anymore (CONTEXT D-08 predates the Azure-PA migration in Phases 05/07). The
`similar` phoneme status is produced by `mapPhonemeOps` in bfa.service.ts purely from Azure's per-phoneme
`AccuracyScore` against two env thresholds:
```typescript
const PHONEME_CORRECT_THRESHOLD = parseInt(process.env.AZURE_PHONEME_CORRECT_THRESHOLD ?? '80', 10);
const PHONEME_SIMILAR_THRESHOLD = parseInt(process.env.AZURE_PHONEME_SIMILAR_THRESHOLD ?? '50', 10);
// score >= 80 → 'correct'; 50 <= score < 80 → 'similar'; score < 50 → 'substituted'; Omission → 'missing'
```
So VOCAB-04 ("cat→cap renders yellow not red") depends on the SIMILAR band [50,80) existing and being
reachable — NOT on a phoneme-pair list. Task 3 verifies this band, it does NOT edit any frozenset.
